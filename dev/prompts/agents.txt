3) contract_orchestrator.py: recursive binary tree per generation: Root Architect -> [CV Specialist, Excavation Control Specialist] -> Independent Verifier.
   - ContractOrchestrator(brain, client, log_fn=print, event_fn=None). event_fn(dict) receives live events {"agent", "status", "message", "generation"} for the HUD tree.
   - ensure_baseline(): if ledger empty, evaluate workspace/baseline_v0.py on opt+holdout seeds, copy to workspace/versions/v0.py and workspace/candidate_pipeline.py, append ledger entry version 0 source "baseline", accepted True (baseline is the reference).
   - run_generation(g): Architect reads playbook + latest opt autopsy (from the best accepted version's evaluation, stored in the brain/ledger entry under key "autopsy"; holdout never has an autopsy) and writes a JSON sub-contract (contract_id, target_rmse_mm, require_top_down_rubble_ordering, max_force_cutoff_n=18.0, latency_ms<25) — via LLM if available else deterministically derived from the autopsy numbers. CV specialist and Control specialist each produce a proposal (LLM: ask for full ExcavationPipeline file given current best source + autopsy + playbook; fallback: FallbackSynthesizer). Merge: if LLM, the control specialist edits the CV specialist's file sequentially (binary tree, two children, merged at the parent); fallback uses the next patch. Write candidate to workspace/versions/candidate_g<g>.py, Verifier runs sandbox on opt seeds with diagnostics and holdout seeds without diagnostics, checks check_contract(opt, holdout, best_opt, best_holdout). If LLM candidate fails the contract, retry once with the fallback patch (so the demo never stalls). Accept -> copy to workspace/versions/v<N>.py and workspace/candidate_pipeline.py (atomic replace), append ledger entry (store opt autopsy too), update playbook with the patch's quantitative findings (actual measured numbers from the evaluation, e.g. "v2: RMSE 31.2->4.1 mm on opt seeds") and on rejection add a graveyard bullet. Record version in SQLite with a unified diff vs previous best.
   - run(iterations, verify_improvement) -> list of entries; if verify_improvement, raise RuntimeError unless opt composite strictly increases each accepted generation and holdout never decreases.
